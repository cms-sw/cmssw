# PhysicsTools/ONNXRuntimeAlpakaTest

Examples and tests for [PhysicsTools/ONNXRuntimeAlpaka](../ONNXRuntimeAlpaka), with the same models used by
[PhysicsTools/PyTorchAlpakaTest](../PyTorchAlpakaTest).

| module | features |
|--------|----------|
| `onnxtest::SimpleNet` | three `SOA_COLUMN`s packed into a `[batch, 3]` input; single-column `[batch, 1]` output used in place |
| `onnxtest::SimpleNet` with `featureMajor = True` | input and output used in place as `[3, padded size]` and `[1, padded size]` tensors, with `SimpleNetFeatureMajor.onnx` |
| `onnxtest::SimpleNetMiniBatch` | mini-batches with `TensorSlice`, in a `stream::EDProducer` whose queue can change from event to event: the session is bound to the queue of the first event, and synchronised with the queue of the following ones when they differ |
| `onnxtest::MultiHeadNet` | two outputs, written directly into the same SoA |
| `onnxtest::MaskedNet` | two inputs, `float` and `uint8_t`, from different SoAs |
| `onnxtest::MaskedNet` with `reverseOrder = True` | the inputs are added in the opposite order of the model inputs, and matched by name |
| `onnxtest::MaskedNet` with `emptyMask = True` | an empty input: the inference is skipped, and the output is filled with zeros |
| `onnxtest::TinyResNet` | `SOA_EIGEN_COLUMN` 9x9 matrices packed into a `[batch, 3, 9, 9]` input, and an Eigen vector output; optionally in mini-batches |
| `onnxtest::ScaledNet` | an `SOA_SCALAR` used in place as a `[1]` input, together with three `SOA_COLUMN`s packed into a `[batch, 3]` input; optionally in mini-batches, including a smaller last batch |

The `onnxtest::InspectionSink` checks the results against the known properties of each model, and fails the job if
any check fails:
  - SimpleNet: the results are finite, and do not depend on the layout or on the mini-batches;
  - MaskedNet: the eta feature is masked out, so the result is `pt + phi`, also when the inputs are matched by name;
    with an empty mask, the result is zero;
  - MultiHeadNet: the regression head is finite, and the classification head is a probability distribution;
  - TinyResNet: the logits are a probability distribution, and do not depend on the mini-batches;
  - ScaledNet: the result is `hitScale * (x + y + z)`, with and without mini-batches.

The `onnxtest::ReferenceAnalyzer` runs SimpleNet, MultiHeadNet and TinyResNet on the CPU with the plain
`cms::Ort::ONNXRuntime` interface of [PhysicsTools/ONNXRuntime](../ONNXRuntime), with the inputs laid out by hand, and
checks that the results of all the variants agree within `1e-4`, relative to `1 + |reference|`. This tests the
shapes, strides, packing and unpacking of the tensors, and the numerical accuracy of the GPU backends; it fails if
TF32 is enabled on the CUDA backend.

The `onnxtest::DataSource` fills the collections with random values that change from event to event, and with the
number of elements given by `--totalSize`; with several values, they are used in turn by the successive events.
The unit tests use `-ts 35 0 1 31 32 33 100`, to test empty collections, single elements, and mini-batches of 32
elements with and without a smaller last batch.

Example run with 100 events, 4 streams, 4 threads, and the `CudaAsync` backend:
```sh
cmsRun ${CMSSW_BASE}/src/PhysicsTools/ONNXRuntimeAlpakaTest/test/runONNXRuntimeAlpakaTest.py -b cuda_async -ne 100 -ns 4 -nt 4
```
Use `--only` to run the selected models; each model is also run as an individual unit test for each backend.
See [python/options_cff.py](python/options_cff.py) for all the options.

## Models

The ONNX models in `data/` are generated by the scripts in `test/`, one per model, e.g.:
```sh
cd ${CMSSW_BASE}/src/PhysicsTools/ONNXRuntimeAlpakaTest/data
python3 ../test/SimpleNet.py
```
`SimpleNet.py` also exports `SimpleNetFeatureMajor.onnx`, the same model wrapped to accept and return transposed
tensors.

For integration in CMSSW, these files should be moved to a `cms-data` repository.
