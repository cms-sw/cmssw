# L1_Phase2: standalone Phase-2 L1 emulation configuration

Target layout of the standalone configuration loaded by `../L1_Phase2_cff.py`
(a `cms.ProcessFragment("L1")`), analogous to `HLTrigger/Configuration/python/HLT_75e33/`.
Tracking issue: https://github.com/artlbv/cmssw/issues/10

| Directory    | Content |
|--------------|---------|
| `modules/`   | EDProducers/EDFilters/EDAnalyzers, one `<label>_cfi.py` each |
| `eventsetup/`| ES sources, ES producers and ES prefers |
| `psets/`     | Shared PSets referenced by modules |
| `sequences/` | Sequences and Tasks |
| `paths/`     | Paths and EndPaths (track trigger, TPs, correlator, GT/menu) |
| `services/`  | Services |

Rules:
* One object per file, file name = process label.
* Fully resolved: no `Modifier`/era logic and no `customise*` hooks; the content
  must equal what `cmsDriver.py -s L1TrackTrigger,L1,L1P2GT` produces for the reference era.
* Not edited by hand (TBD): files are regenerated by a script, so changes belong in the
  live `_cfi`/`_cff` files plus a regeneration.
* Module labels must stay identical to the current ones (DQM, ntuplizers, HLT inputs).
